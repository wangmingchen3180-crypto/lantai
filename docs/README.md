# 文档索引

澜台的所有计划、决策和规格都在 `docs/` 这一个目录里。根目录只留 `README.md`（对外介绍）和 `CONTRIBUTING.md`（怎么参与）。

**新决定往哪写**：先看下面这张表有没有对应的文件，有就写进去，没有再新建。不要在根目录新建计划文件，也不要把同一件事写进两个文件——重复的记录一定会有一份先过期。

| 文件 | 装什么 | 什么时候写 |
| --- | --- | --- |
| [BACKLOG.md](BACKLOG.md) | 版本路线、未做事项、已落地记录、待决策问题、踩过的坑 | 定了要做什么、做完了某一块、或记下一条不能再忘的教训 |
| [UI_ARCHITECTURE.md](UI_ARCHITECTURE.md) | 改 UI 的实际成本、皮肤边界、新界面规矩、以及为什么不做「一切皆插件」 | 动界面结构、抽 token、考虑换皮或插件化之前 |
| [DESIGN.md](DESIGN.md) | 涟漪设计语言、视觉规格、身份件（图标 / Logo / 空状态） | 改视觉规格、画图标 |
| `BRIDGE_API.md` | 手机端与 Mac 端之间的协议契约 | 改接口、加字段、加事件类型 |
| [AGENT_ADAPTERS.md](AGENT_ADAPTERS.md) | 接入各家 Agent 的适配器边界与健康度语义 | 接新 Agent、改数据源探测 |
| [NAMING.md](NAMING.md) | 命名决策与改名时刻意没改的东西 | 改显示名、改标识符 |
| [prototypes/](prototypes/) | HTML 原型。是探索记录，不是产品依据 | 试新界面方向 |
| [images/](images/) | README 配图，由 `--shot` 自渲染生成 | 界面变了要重出图 |

`BRIDGE_API.md` 暂时没有链接：它随第一阶段的手机端 / Bridge 一起进仓库，那批改动目前还只在本地未提交。

几条避免文档本身变乱的规矩：

- **决策要连理由和代价一起写。** 只写「决定用 A」，三个月后必然重开一轮同样的讨论。
- **推翻旧决定时，把旧的划掉留在原处**（`~~删除线~~` + 指向新结论），不要直接删。踩过的坑删掉就会再踩一次。
- **数字要写来源。** 「约 160 个字面量」这类结论要附上能重跑的命令，否则没人知道它是否还成立。
- **本机未入库的代码，计划里要写明。** 2026-08-14 的 Bridge / 手机端 / 配对卡已经在用户 Mac 上跑通，但还没进这个 git 仓库。`BACKLOG.md` 把状态标成「本机已落地，未入库」，避免后人以为 `main` 上已经有这些文件。
