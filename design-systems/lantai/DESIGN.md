# 澜台设计系统

这份文件是**唯一的 token 真相**。手机端 CSS 变量、Mac 端 AppKit 常量、以及任何工具（Open Design 等）渲染澜台界面时，都必须从这里取值。

数值不是设计师拍的，是从已经上线的代码里抽出来的，可复核。抽取命令见文末「怎么复核」。

- 视觉语言与涟漪规格（层数、周期、曲线）见 [`docs/DESIGN.md`](../../docs/DESIGN.md)。**本文件不重复涟漪规格。**
- 改 UI 的成本、皮肤边界、新界面必须守的三条规矩见 [`docs/UI_ARCHITECTURE.md`](../../docs/UI_ARCHITECTURE.md)。

## 硬约束（渲染前先读，违反即返工）

1. **只有深色。** 窗口强制深色，不做浅色皮肤。下面 `light` 槽装的也是深色值——它是 macOS 浅色外观下的基调，不是白底主题。
2. **状态色是语义，不许换。** 绿=已就绪、橙=需关注/等待、红=失败、蓝=运行中。换一套皮肤就要重新教用户认颜色，所以状态色不参与换肤。
3. **涟漪只表示「有东西在活着」。** 不铺到任务卡、待办行、按钮、返回入口。全都在动等于都不动。
4. **不要发明新的间距和字号。** 只用下面梯度里的值。要用梯度外的值，先改这份文件并说明理由。
5. **不许出现绝对路径。** 界面上的项目路径一律脱敏成 `~`。
6. **空状态要分两种。** 「暂无任务」是平静（画静止水面）；「数据源不可用」必须是明确的故障文案，不能画成空水面。

## 颜色

`light` / `dark` 两槽按 macOS `effectiveAppearance` 切换；高对比模式下亮通道再提亮、暗通道再压暗。手机端只用 `dark` 槽。

```yaml
color:
  accent:  { light: "#5280FF", dark: "#668FFF" }   # 强调、选中、主按钮
  bg:      { light: "#181A22", dark: "#13151C" }   # 窗口底
  surface: { light: "#252832", dark: "#20222C" }   # 卡片、行、输入框底
  border:  { light: "#4C5060", dark: "#555969" }   # 控件描边
  fg:      { light: "#EDEDF1", dark: "#F2F2F5" }   # 主文字
  fg2:     { light: "#BDBEC6", dark: "#C7C7CF" }   # 次要文字
  muted:   { light: "#94959E", dark: "#9E9FA8" }   # 提示、计数、时间戳
  hairline: "rgba(255,255,255,0.08)"               # 嵌入式描边,比 border 柔和一档(浅色外观 0.10)
status:
  working:   { light: "#6B96FF", dark: "#7AA3FF" }  # 运行中
  attention: { light: "#FF9E3D", dark: "#FFA84C" }  # 需关注 / 等待
  failed:    { light: "#FF6B6E", dark: "#FF787A" }  # 失败
  ready:     { light: "#54DB73", dark: "#61E380" }  # 已就绪
  idle:      "muted"                                # 空闲复用 muted
shadow:
  card: "rgba(20,20,22,0.12)"   # 工作台
  hud:  "rgba(20,20,22,0.18)"   # HUD / 悬浮球
```

阴影色目前在代码里是直写的字面量（7 处绕过调色板），已记为待收拢项。新界面请用上面的 `shadow` token，不要再直写。

## 节奏与气质（比 token 更决定「像不像澜台」）

token 只能防丑，不能生成好看。真正让人觉得「这是澜台」的是下面这些，全部从已上线的工作台里抽出来，**新界面照抄**。

违反这一节的界面，色值再对也会显得像另一个产品——这是 2026-08-14 一次 AI 生成原型被否的直接原因：它只拿到了 token，没拿到节奏。

### 行是透明的，不是卡片

现有任务行（`taskRow`，520 宽里最重要的一种行）：

```yaml
task-row:
  height: 56
  radius: 10
  background: transparent      # 不是填充卡片!
  hover-wash: 0.04             # 4% 白,几乎看不见
  pressed-wash: 0.07
  padding-x: 12
  dot: 7                       # 状态只用 7pt 圆点,永不用 badge / 填充胶囊
  dot-to-text: 10
  title: { size: 12, weight: medium, color: fg }
  meta:  { size: 11, weight: regular, color: muted }
  title-meta-gap: 1            # 两行几乎贴着,合成一块
```

三件事要特别注意，它们最容易被做错：

1. **行没有底色、没有描边。** 只有 hover 时加 4% 白。整张卡片靠留白和字重分层，不靠框线分层。任何「每行一个带边框的卡片」都是错的。
2. **标题与副行只隔 1pt。** 它们要读成一个整体，不是两行。给到 4、6、8 就散了。
3. **状态永远是 7pt 圆点。** 不用彩色标签、不用填充胶囊、不用背景色块。

现有待办行（`todoRow`）比任务行更轻一档：

```yaml
todo-row:
  height: 30
  radius: 6
  title: { size: 12.5, weight: regular, color: fg2 }   # 注意是次级前景,不是 fg
  completed-title-color: muted
  checkbox: { symbol: 15, hit-area: 22, unchecked: muted, checked: green }
  editing-background: "accent @ 10%"
  editing-radius: 4
```

**待办标题刻意用次级色 `fg2`**，比任务标题（`fg`）低一档。待办在澜台里是配角，不该抢 Agent 的注意力。四象限沿用这个层级。

### 运动

```yaml
motion:
  hover-in: 0.12
  hover-out: 0.15      # 出比进慢,离开时不突然
  panel: 0.18 ~ 0.22   # 窗口/面板级(HUD 探出、悬浮球贴边)
  easing: ease-out     # 不要弹跳、不要 overshoot
  ripple: 8 ~ 14s      # 环境级慢动作,只用于「有东西在活着」
```

**四象限的胀开/缩回按 `panel` 档（0.20）。** 这个动画是整套交互的成败所在：瞬间切换会显得廉价，超过 0.3 秒会显得拖。缩回要略慢于胀开，和 hover 同理。

只动几何（尺寸、位置、透明度），不要动颜色，不要加位移弹跳。

### 密度取舍：一格里别塞四样东西

`250×66` 的格子里放不下「名字 + 说明 + 条数 + 两条预览」四层信息，硬放必然显得挤和吵。**四格态只放三样：名字、条数、两条预览。那行说明只在满格态出现。**

判断标准：一个格子里的文字层级不超过三级。超过就砍，不要靠缩字号解决。

代码里的实际分布（出现次数）：`10`×6、`8`×5、`16`×2、`7`×2、`6`×2、`2`×2、`4`/`12`/`14`/`18` 各 1。收敛成四档，括号里是它现在的用处：

```yaml
radius:
  card: 10    # 工作台卡片、待办卡片
  row: 8      # 待办行、任务行、输入框、胶囊
  chip: 6     # 小标签
  orb: 16     # 悬浮球、HUD 圆角容器
  hairline: 2 # HUD 手柄这类极小构件
```

`12` / `14` / `18` 是历史遗留，新界面不要再用。

## 字号

实际分布：`11`×5、`12`×5、`12.5`×3、`9`×2、`10`/`13`/`14`/`22` 各 1。

```yaml
font:
  display: { size: 22, weight: semibold }  # 悬浮球/大数字
```

## 待办四象限：这一版要渲染的东西

核心是一个**满格接管 / 再点缩回**的开关，只有两个状态，没有中间态：

- **四格态（默认）**：四格平分，每格只有格名 + 小号条数，其余全部留白。说明行与条目预览都不出现在这里，理由见下面「四格态显示什么」。
- **满格态**：点一格，该格胀满整个待办区，**其余三格完全不显示**——不是缩成窄条，是消失。这一格拿到全部宽度，能录入新条目并看全量列表。
- **再点一次缩回**：点该格标题、点空白、或按 Esc，回到四格态。
- **换格必须先缩回。** 满格态里看不到别的格子，所以没有直接跳格这回事。这是刻意的：录入时不给你切走的机会。
- **点条目即完成**：两个状态下都能点一条待办直接标完成，不必先把那格放大。
- **录入要专心**：满格态默认焦点在输入框，那一屏不堆筛选器、排序按钮、设置。这是这套交互唯一的价值所在。
- **四象限来源**：`urgent` / `important` 两个布尔的组合，不是枚举字段。拖到另一格 = 改一个布尔。

手机上满格态的物理表现是整页接管 + 左上角返回箭头，逻辑上是同一个开关。

### 四格态显示什么（定案：设计一，2026-08-14）

**只有格名 + 小号条数**（沿用现有 `10.5pt` `muted` 胶囊）。空格显示极淡的 `—` 而不是 `0`——主角自然落在「唯一有内容的那格」，不必靠放大数字制造重心。说明行与条目预览都只在满格态出现。

定案依据是第一版原型量出来的高度账：四格态每格可用 `59px`，名字 + 说明 + 两行预览要用 `58px`，**只剩 1px 留白**。设计二（带预览）不是不能实现，是实现出来必然憋闷。详细评审见 [`docs/UI_ARCHITECTURE.md`](../../docs/UI_ARCHITECTURE.md)。

砍掉说明与预览之后，每格 59px 只需装名字（16.5）+ 条数（同一行），剩下 40 多 px 全是留白——这才是澜台该有的呼吸感。

~~设计二 · 预览：格名 + 条数 + 两行条目预览~~ 已弃用（留白只剩 1px）。

无论选哪个，**条数都不许做成大号数字**。现有计数是那条横条里最轻的一样东西（10.5pt muted），待办标题也刻意比任务标题低一档；把数字放大会让它成为整个工作台最响的元素，那是仪表盘的层级，不是工作台的。

### 空间账

展开区是 **520×158**（`todo.expanded-extra` 为 210 时的结果，那个数字当初是为「5 行线性列表」定的）。减去顶部待分类横条约 20，两个状态各自的账：

- **四格态**：四格各约 250×69，减内边距后可用 `59px`。只放格名一行（约 16.5），**剩下 40 多 px 全是留白**。这是刻意的：四格态是选择器，不是列表。
- **满格态**：一格独占约 520×138 —— 输入行 32 + 四行列表，够读够录。

满格接管把压力从四格态卸掉了：四格态只负责「让你看见四个格子各有什么」，看全和录入都在满格态完成。所以两行预览是够的，不是妥协。

展开高度是否要加大仍未拍板（**A** 守住 158 / **B** 加大到约 300 让每格三行 / **C** 四象限单开更大的视图）。原型按 **A** 画：A 是下界，A 里读得通，B/C 必然读得通，反过来不成立。**这是尺寸决策，按某个宽高把细节排完就会锁死，要在写 AppKit 之前定。**

### 四格的位置与叫法

**位置是约定，不是谁的原创。** 沿用艾森豪威尔矩阵的通行画法：**重要在上排、紧急在左列**。这样从左上往右下读，正好是「该先看哪个」的顺序，不用在脑子里换算。（用户提供的参考图把重要不紧急放在左上，那只是举例，不作为依据。）

叫法走水象，和涟漪、澜台同一套意象。**四个字必须互不相同且两两成对**——这是选词的判据，不是修辞偏好。

判据：一个名字里挑出来的那个特征字，四个放在一起要能看出两条轴。

- 竖着看要分出**动 / 静**（急这条轴）
- 横着看要分出**深 / 薄**（要紧这条轴）

**定案（2026-08-14 用户拍板）：**

| 位置 | important | urgent | 名称 | 特征字 | 一行说明 |
| --- | --- | --- | --- | --- | --- |
| 左上 | 是 | 是 | 急流 | 急 | 卷着走，先过这一段 |
| 右上 | 是 | 否 | 深潭 | 深 | 要沉下去做，别搁浅 |
| 左下 | 否 | 是 | 碎浪 | 碎 | 琐碎又催人，蹚过去就完 |
| 右下 | 否 | 否 | 静水 | 静 | 没动静，想不起来也无妨 |

急 / 深 / 碎 / 静 四字互不相同，且两条轴都读得出：

- **动静轴**：急流、碎浪都在动（流、浪）；深潭、静水都不动（潭、水）。
- **深薄轴**：急流、深潭都有体量（流成势、潭见底之下还有水）；碎浪、静水都只在表面（浪是水面碎开，静水是什么也没发生）。
- `碎` 正对中文里说小事的那个词——**琐碎**。急但不要紧的事，本质就是琐碎又催人。

落选但留着的两条路（若日后觉得水象太绕）：

**备选一（完全对称，两条轴都直接拼在字面上）：** `急流` / `缓流` / `急滩` / `缓滩`。急—缓、流—滩两组各管一轴，零翻译成本。落选原因：四个名字长得太像，扫一眼容易点错格，且读起来像水文术语不像产品语言。

第四格考虑过的其他字，记下来免得重开一轮：`漩`（漩涡，原地打转很准，但带险意会被读成要紧）、`沫`（够轻但不够急）、`溅`（够急但不够轻）、`湍`（显凶，像要紧事）。`碎` 胜出是因为它直通中文说小事的那个词——琐碎。

**备选二（退路）：** `急重` / `徐重` / `急轻` / `徐轻`。名字即坐标，最省脑，但完全没有水象。

弃用记录，别再提回来：

- ~~`现在做` / `早点做` / `顺手做` / `先放着`~~ —— 准确但没味道，和「澜」不搭。
- ~~`浅滩`~~ —— 显不出「急」。
- ~~`急滩`~~ —— 补上了急，但和 `急流` 共用一个字，等于四格只剩三个特征字；且当时 `深潭` / `静水` 都读作「不动」，右列两格也撞。四个字必须互不相同这条判据就是从这里来的。

**硬条件：** 网格边缘必须标出两条轴（上排写「要紧」、左列写「急」），每格下面必须有那行说明。四个字互不相同之后，轴就不在名字里了，所以边缘标签从「最好有」变成**必须有**。诗意的名字只能是结构之上的装饰，不能替代结构——否则用户扔一条待办时要停下来翻译，那一下停顿就是成本。

### 待分类：留 Agent 口子之后必须有的第五块

一旦允许 Agent 或 API 替你建待办，就必须有一个「还没判断轻重」的落点，理由是：`urgent` / `important` 若默认 `0`，Agent 建的待办会静静掉进**先放着**——四格里你最少看的那一格。等于口子建好了，进来的东西自动被藏起来。

所以：

- `urgent` / `important` **允许为空**。空 = 还没判断，不等于「不重要不紧急」。
- 总览顶部一条窄横条：`待分类 N`。点开是同样的接管态，逐条指派到某一格。
- 这条横条同时服务人：你自己随手记一句、还没想清轻重，也进这里，不用被迫先选格子。
- Agent **主动建议**的待办只进待分类，不许直接落进四格；用户**明确要求**建的，可以带着格子直接落。

总览的五块在 Mac 的 158 高里这么分：待分类横条约 20，四格各约 66。接管态下横条保留，四格中的三格收成约 18 的窄条。

### 每一格里还要有的东西

截止时间（今天到期用 `status.attention`，已过期用 `status.failed`）、拖拽排序（同格内）、来源标记（Agent 待办显示来源并能回跳原会话）、已完成折叠到底部归档区。

手机端用同一套交互和同一套叫法，不要为手机另设计一套。窄屏摊不开 2×2 的信息量，就少显示标题预览，但格子的位置、名字、顺序必须一致。

## 怎么复核这些数字

```bash
cd "$(git rev-parse --show-toplevel)"
# 颜色源头（CPDyn 的 12 个调色板函数）
rg -n "^NSColor \*CP" Sources/CodexPulse/CPStatusEngine.m
# 圆角、字号、间距的实际分布
rg -o "cornerRadius = [0-9.]+" Sources/CodexPulse/*.m | sort | uniq -c | sort -rn
rg -o "FontOfSize:[0-9.]+" Sources/CodexPulse/*.m | sed 's/.*://' | sort -n | uniq -c
rg -o "constraintEqualToConstant:[0-9.]+|constant:-?[0-9.]+" Sources/CodexPulse/*.m | sed 's/.*://' | sort -n | uniq -c | sort -rn
# 固定几何常量
rg -n "^const CGFloat CP" Sources/CodexPulse/*.m
```

浮点 → 十六进制的换算是 `round(v * 255)`，与手机端现有 CSS 变量完全一致（`accent #668FFF`、`bg #13151C`、`surface #20222C` 三处已交叉验证）。
